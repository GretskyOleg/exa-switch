# EXA Switch — что это и зачем

**EXA Switch** — браузерное расширение + локальный helper с **xray-core**, которое
позволяет пускать через VLESS/Reality **только выбранные сайты**, а всё остальное
открывать напрямую. По ощущениям — Proxy SwitchyOmega, но с настоящим VLESS-туннелем.

```
┌──────────────────────────────┐        native messaging         ┌──────────────────────────────┐
│  Расширение (Firefox/Chrome) │ ──────────────────────────────▶ │  xray-switch-helper          │
│  • профили VLESS             │                                 │  • держит xray-core          │
│  • правила сайтов            │        HTTP API + token         │  • SOCKS5 / HTTP на loopback │
│  • popup / options           │ ◀─────────────────────────────▶ │  • health, logs, restart     │
└──────────────┬───────────────┘        127.0.0.1:<random>       └──────────────┬───────────────┘
               │ chrome.proxy / browser.proxy                                   │ VLESS / Reality
               ▼                                                                ▼
        Трафик браузера ───────────────────────────────────────────────▶  ваш VLESS-сервер
```

## Зачем это нужно

Обычный VPN заворачивает **весь** трафик системы. Это неудобно, если:

- нужен доступ только к паре сайтов, а остальное должно идти напрямую;
- системный VPN ломает банки, госуслуги, локальную сеть и игры;
- хочется держать разные профили под разные задачи и переключать их на лету;
- нужно быстро сказать «этот сайт — через прокси, этот — напрямую».

EXA Switch делает это на уровне браузера: правила по домену, режимы «Авто» и «Всё»,
переключение текущего сайта из popup и контекстного меню.

## Почему нужен helper

Браузер физически не умеет открывать VLESS/Reality и не может быть SOCKS-сервером:

1. `chrome.proxy` / `browser.proxy` умеют только «отправь запрос на TCP-прокси» (SOCKS5/HTTP).
2. Расширение не может слушать входящий порт — это запрещено моделью безопасности браузера.
3. Поэтому отдельный процесс helper держит xray-core и отдаёт `127.0.0.1:<socks>`.

Расширение лишь говорит браузеру, какие сайты отправлять на этот SOCKS. Сам helper
работает с правами пользователя, слушает только loopback и требует токен.

## Возможности

- VLESS: **Reality**, **TLS**, **WS**, **gRPC**, **XHTTP**, **HTTPUpgrade**, **KCP**,
  `xtls-rprx-vision`.
- Импорт одной или нескольких ссылок `vless://` и base64-подписок.
- Профили с переключением на лету.
- Правила: `example.com`, `*.example.com`, `*google*`, «напрямую», «прокси».
- Режимы:
  - **Выкл** — весь трафик напрямую, ядро останавливается.
  - **Авто** — прокси только для сайтов с правилом `proxy`.
  - **Всё** — прокси для всего, кроме правил `direct`.
- Локальные адреса (`localhost`, `10.*`, `192.168.*`, `172.16-31.*`, `127.*`, `::1`)
  всегда идут напрямую.
- Проверка туннеля, логи ядра, перезапуск helper'а.
- Экспорт/импорт настроек.
- Firefox: `proxy.onRequest` — правила применяются сразу, без PAC.
- Chrome: PAC-скрипт (только по хосту).

## Где хранятся данные

| Что | Где | Права |
|---|---|---|
| Профили, UUID, правила | `chrome.storage.local` расширения | sandbox браузера |
| Порт и 256-битный токен helper'а | `~/.config/xray-switch/daemon.json` | `0600`, каталог `0700` |
| Логи helper'а | journal (`journalctl --user -u xray-switch`) | только пользователь |
| Логи ядра (кольцевой буфер) | в памяти helper'а | — |

Ничего не отправляется на сторонние серверы. Подписка скачивается только по кнопке
и только после явного разрешения на домен. Телеметрии нет.

## Ограничения (честно)

- **Только VLESS.** VMess/Trojan/Shadowsocks в подписках пропускаются.
- **Только трафик браузера.** Это не системный VPN; другие приложения идут напрямую.
- **Нет UDP/WebRTC.** UDP-ассоциации у SOCKS выключены.
- **Chrome — PAC и только по хосту.** Правила по путям/заголовкам не поддерживаются.
- **Полный JSON-конфиг xray не импортируется.** Только VLESS-ссылки.
- `allowInsecure` в xray 26.x игнорируется; `h2`/`quic`/legacy XTLS удалены.
- **DNS адреса VLESS-сервера** резолвится системным DNS; целевые домены уходят
  на сервер через SOCKS/HTTP.
- **Flatpak/Snap браузеры** могут не видеть native host.

## Безопасность

Подробный разбор угроз и исправлений — в [SECURITY.md](SECURITY.md).
Коротко: helper слушает только loopback, API защищён токеном, CORS ограничен
origin расширения, helper принимает только VLESS-клиентские outbound'ы, а
systemd-служба работает с `NoNewPrivileges` и `ProtectSystem=full`.
